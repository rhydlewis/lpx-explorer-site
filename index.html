The problem

Hundreds of old projects. No idea what's in any of them.

If you've used Logic for years, you have a folder full of projects with names that tell you nothing. Opening each one to jog your memory means waiting for Logic to launch, then waiting for the project to load — and sometimes discovering a plug-in is missing only once you're already there.

LPX Explorer answers two questions instantly: what's in this project? and will it open cleanly on this Mac?

What it does

Two ways in: a single project, or your whole library.

Inspect a project

Pick a project, see the details

  • Compatibility verdict — clean, warnings, or will-not-open — with a jump straight to the first missing plug-in.
  • Project metadata: key, BPM, time signature, sample rate, dates and bundle size.
  • Track list with user-renamed names recovered from the project, and expandable insert chains as colour-coded pills.
  • Plug-in rail showing every Audio Unit the project references, with install-status badges checked against your Mac.
Instrument FX MIDI
Scan a folder

Pick a folder, see the library

  • Recursive scan of every .logicx bundle, with progress and a per-project cache.
  • Tile grid showing name, key + BPM, track counts and size at a glance.
  • Searchable sidebar; recent projects and folders surface in the native File menu.
  • Plug-in sidebar flips to library scope: e.g. 47 plug-ins · 3 missing across 12 projects.

Tested against ~150 projects across ~25 GB.

Compatibility check

Know before you open it.

LPX Explorer cross-references the Audio Units a project references against the plug-ins actually installed on your machine — so you find out about a missing instrument before Logic does.

Clean

Every referenced plug-in is installed. Open with confidence.

Warnings

Some plug-ins are missing or substituted. You can search for or copy the fingerprint of each one.

Will not open

Critical components are unavailable on this Mac. Sort it out first.

Read-only by construction

It cannot change your files. That's enforced, not promised.

Your projects are irreplaceable. LPX Explorer is built so that touching a file's contents is structurally impossible — and that guarantee is tested in CI.

Bytes-only parser

The Rust parser has a bytes-only API — find_aus(&[u8]), find_tracks(&[u8]). It is given bytes; it cannot open or write a file.

Read once, route through

The Tauri command layer reads a bundle's bytes a single time and passes them to the parser. Nothing writes back.

Proven by invariant

An integration test snapshots SHA-256 + mtime around the parser and asserts not a single byte changed.

Gated, not aspirational

CI fails if the read-only invariant fails. The guarantee can't quietly rot between releases.

⚠

Still: keep backups. LPX Explorer parses an undocumented binary format that Apple may change at any time. The read-only invariant covers the parser, but you're pointing it at irreplaceable creative work. Use at your own risk.

FAQ

The honest answers.

Which platforms are supported? +

macOS only. It's a native Tauri app for Apple silicon and Intel Macs. There's no Windows or Linux build, because Logic Pro is macOS-only.

Does it work with VST or AAX plug-ins? +

It checks Audio Unit (AU) plug-ins only — the format Logic uses. The registry is built by running auval -l once at startup and cached for the session, with a manual rescan when you install something new.

Can it edit or repair my projects? +

No, and that's deliberate. It's read-only by construction — it inspects, it never writes. If you need to fix a project, do it in Logic.

Why does it sometimes list plug-ins I'm not using? +

Two known quirks, both real rather than bugs: Logic keeps prior plug-in references in ProjectData after you swap one (undo history), and other Alternatives inside the bundle carry their own references. Open the project in Logic to see what the active alternative actually loads.

How much does it cost? +

It's free and open source under GPL-3.0. If it's saved you some time, donations are welcome but never required, and nothing is gated behind them.

How does this relate to lpx-toolkit? +

lpx-toolkit is the original Python CLI, built first to reverse-engineer the .logicx structure. LPX Explorer is the desktop app, with the format knowledge now living in a Rust parser crate that both will eventually share.
